# JAFAR 2.1 — рабочие замечания юриста в черновике Word (бета)

## Цель

Связать найденные программой предполагаемые расхождения с подготовкой
процессуального документа, сохранив ответственность юриста за содержание.
Эта функция НЕ переносит выводы модели в фактическую или просительную
часть жалобы, ходатайства либо апелляции.

## Как использовать

1. Открыть выбранное дело в «Юстиции» и проверить два или более документа
   в разделе «Аналитика» → «Расхождения в обстоятельствах».
2. По нужному кандидату вручную записать решение «Оставить для работы»
   и собственное пояснение. Не использовать этот статус как подтверждение факта.
3. В разделе «Шаблоны» → «Подготовка процессуального документа»
   выбрать соответствующие исходные документы и отметки из журнала.
4. Заполнить адресата, заявителя, собственное изложение обстоятельств,
   проверенные правовые основания и просительную часть.
5. Запросить предварительный просмотр и явно сохранить Word.
6. Открыть Word, проверить реквизиты, материалы и служебную страницу.
   Служебную страницу удалить при подготовке документа для внешней подачи,
   если она не предназначена для приложения.

## Технический механизм

У LegalDraftRequest добавлено необязательное поле review_record_ids,
ограниченное 12 неповторяющимися непустыми идентификаторами. Старые
черновики продолжают читаться без поля и получают пустой список.

В начале предварительного просмотра сервис:

- удостоверяется в существовании Matter;
- подтверждает, что каждый выбранный исходный документ принадлежит делу,
  доступен и проходит проверку целостности зашифрованного оригинала;
- получает доступ к локальному зашифрованному журналу;
- сверяет все указанные записи с выбранным Matter;
- разрешает только самое последнее решение по кандидату со статусом
  keep_for_work. Если позже была запись dismissed либо needs_sources,
  старая запись не может попасть в новый Word;
- требует, чтобы оба исходных документа были выбраны пользователем;
- проверяет техническую ссылку на индексированный фрагмент и дословное
  наличие обеих исходных цитат в актуальных текстовых фрагментах;
- проверяет совпадение названий исходных файлов.

Неизвестное решение и чужой Matter возвращают 404; отсутствующий
журнал — 404; отклонённая/устаревшая запись, повреждённые данные и
несовпадение цитаты блокируют сборку документа с 409.

При успешной проверке заметки добавляются только после разрыва страницы,
в раздел «РАБОЧИЕ ЗАМЕЧАНИЯ ЮРИСТА (ВНУТРЕННЯЯ ПРОВЕРКА)».
Содержимое высказываний НЕ вставляется в основной текст, правовые
основания или просительную часть, даже при выборе пользователя.

## Конфиденциальность

Все операции происходят в локальном macOS runtime, защищённом
сессионной авторизацией. Журнал зашифрован и привязан к Matter.
Дополнительных обращений к Ollama либо внешним AI-провайдерам для
вставки замечаний нет. Не возникает отправки клиентского документа
по почте, в Telegram, Supabase либо непосредственно в суд.

При сохранении рабочего черновика выбранные record_id остаются частью
зашифрованной истории редакций черновика, без сохранения заметок в
незашифрованных настройках приложения.

## Проверки

Применяются синтетические примеры, не сведения реальных клиентов:

- выбранное решение попадает только во внутренний раздел DOCX;
- старое keep_for_work после dismissed не допускается;
- источник, не выбранный в деле, не допускается;
- изменённая цитата, чужое дело либо отсутствующая запись блокируют экспорт;
- старые JSON-черновики читаются без нового поля;
- защищённый API повторно проверяет заметки при Word export.

Перед использованием с реальными делами необходимы полный CI,
Apple iOS/macOS Build, macOS Packaging и ручное испытание на чистом Mac.

Ограничения: принадлежность цитаты исходному фрагменту не доказывает
корректность AI-классификации, правовой оценки либо подлинность документа.
