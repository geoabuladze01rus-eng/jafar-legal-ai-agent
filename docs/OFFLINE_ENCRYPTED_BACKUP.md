# JAFAR 2.1 — безопасное резервное копирование (macOS, закрытая бета)

## Что реализовано

Отдельная офлайн-команда создаёт резервный архив из локальных
зашифрованных баз JAFAR и зашифрованных оригиналов:

- matters.sqlite3 — карточки дел и события;
- corpus.sqlite3 — текстовые фрагменты, метаданные, источники;
- documents/*.jafarblob — оригиналы, перечисленные в индексе корпуса;
- drafts.sqlite3 — история черновиков, если она существует;
- claim-review-decisions.sqlite3 — журнал решений юриста, если существует.

Исходные файлы остаются на месте. SQLite копируется штатным SQLite
backup API с учётом WAL. Список оригиналов сверяется с индексом
корпуса. Отсутствующий или повреждённый файл блокирует операцию.

Отдельная парольная фраза используется для Scrypt с новой солью
и AES-256-GCM каждого вложенного файла. Внутри ZIP содержатся
зашифрованные объекты и зашифрованный манифест с SHA-256 и размерами.
В открытом заголовке есть только версия, соль и алгоритмы.
Тексты клиентов и имена документов не раскрываются в заголовке.

## Приложение должно быть закрыто

JAFAR и его sidecar нужно полностью завершить ДО резервирования.
Команда проверяет эксклюзивную блокировку matters.lock. Если приложение
работает, операция прекращается без создания архива.

Облачная база Supabase не затрагивается.

## Использование из исходного репозитория

Нужен Python 3.11+ и установленные зависимости проекта.

Создать архив:

~~~bash
python -m jafar.desktop_backup create \
  --home "$HOME/Library/Application Support/JAFAR" \
  --output "$HOME/Documents/jafar-private-backup.jafarbackup"
~~~

Проверить архив:

~~~bash
python -m jafar.desktop_backup verify \
  --archive "$HOME/Documents/jafar-private-backup.jafarbackup"
~~~

Восстановить только в НОВЫЙ каталог:

~~~bash
python -m jafar.desktop_backup restore-new \
  --archive "$HOME/Documents/jafar-private-backup.jafarbackup" \
  --target "$HOME/Documents/JAFAR-RESTORED-TEST"
~~~

Пароль вводится в скрытом приглашении, не аргументом командной строки.
Для создания требуется отдельная парольная фраза не короче 16 символов.

## Что проверяется до восстановления

1. Поддерживаемый формат архива, метаданные, обязательные базы.
2. AES-GCM каждого объекта и манифеста, введённый пользователем пароль.
3. SHA-256 и длина каждого вложенного файла.
4. SQLite quick_check всех копий баз.
5. Полное соответствие файлов-оригиналов индексу корпуса.
6. Допустимые пути и запрет нераспознанных ZIP-объектов.

Лишь после этого создаётся отдельный пустой каталог. Уже существующий
каталог, даже пустой, никогда не перезаписывается. Клиентские данные
не публикуются и не загружаются в облако.

## Главный риск восстановления на другом Mac

**Архив НЕ содержит мастер-ключ JAFAR из Keychain.**

Пароль архива снимает только дополнительный слой шифрования.
Для открытия баз и документов всё равно требуется ИСХОДНЫЙ
мастер-ключ приложения в Keychain. Если он утрачен, пароль резервной
копии НЕ восстановит доступ к делу.

Процедура защищённого переноса мастер-ключа между устройствами
пока не реализована. Поэтому данный инструмент защищает от утраты
файлов при сохранённом Keychain-ключе, но не гарантирует восстановление
после полной утраты компьютера.

Проверка архива удостоверяет шифрование резервной копии, контрольные
суммы и структуру SQLite. Она не подтверждает внутреннюю расшифровку
каждого документа на новом Mac и не доказывает подлинность судебных
доказательств.

## Ограничения

- macOS/POSIX, закрытый sidecar. Не версия для Windows.
- Python CLI из исходного проекта. Нет кнопки в приложении, потому что
  приложение должно быть закрыто.
- Максимум 10 000 файлов, 256 МБ на файл и 8 ГБ общего содержимого.
- Нет автоматического расписания, облачной синхронизации, ротации,
  восстановления в действующий профиль или миграции ключей.
- Не заменяет FileVault и организационные меры адвокатской или иной
  профессиональной конфиденциальности.

## Приёмка

Синтетические проверки: блокировка при работающем приложении, полный
цикл создания/проверки/восстановления, неверный пароль, изменённый
шифротекст, отсутствующий оригинал, защита от перезаписи, недопустимые
пути, отсутствие открытых клиентских данных, сохранность оригинальных
ключей. Затем GitHub CI и ручной тест на чистом Mac.

До этих проверок функция не предназначена для архивов реальных клиентов.
