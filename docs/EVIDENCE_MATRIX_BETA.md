# JAFAR 2.1 — локальная матрица сверки доказательств (beta)

## Назначение

Сопоставить несколько выбранных документов одного дела по явно подписанным
значениям. Это проверочная справка юриста, не доказательство противоречия и не
автоматический процессуальный документ. Никакие выводы о достоверности
показаний, умысле, вине, достаточности доказательств или применимом законе
программа не делает.

## Вход и обработка

1. В разделе «Аналитика» выбрать дело, затем от двух до двенадцати
   локально импортированных документов. При желании указать предмет сверки.
2. Сервер проверяет, что каждый документ находится в выбранном Matter, имеет
   статус READY и его зашифрованный оригинал проходит проверку целостности.
3. Сопоставление выполняется локально, без вызова Ollama или облачных моделей.
   Анализируются только явно подписанные поля:
   «дата договора / дата заключения договора / дата подписания договора»,
   «дата платежа / дата оплаты»,
   «сумма договора / стоимость договора»,
   «сумма задолженности / размер задолженности»,
   «сумма платежа / сумма оплаты».
4. Даты приводятся к календарному ISO-представлению, рублёвые суммы к
   двухзначной десятичной форме. Неверные даты и числа не используются.
5. Для каждого значения сохраняются имя файла, идентификатор документа,
   технический источник (document/page/chunk) и исходная строка.

## Правила сверки

- Значения из одного файла не сравниваются с ним же как «два источника».
- Если значение поля появилось в двух и более файлах, фиксируется
  same_labelled_value (значение совпадает),
  possible_difference (значения отличаются) или
  ambiguous_within_document (внутри файла обнаружено несколько разных
  значений того же поля).
- Даже при possible_difference программа не утверждает противоречия:
  одинаковая подпись поля может относиться к разным договорам и операциям.
- Остальные извлечённые поля показываются как «без достаточной пары».
- Отсутствие отмеченных различий ничего не доказывает о согласованности
  свидетельских показаний, справок, расчётов и иных материалов.
- Текущий локальный импорт назначает всем фрагментам source_page=1;
  ссылка является техническим идентификатором и не подтверждает страницу
  исходника или лист дела. OCR и сканы нужно сверять визуально.

## Безопасность

- API существует только в desktop runtime при наличии зашифрованного корпуса.
- Все вызовы /v1 защищены сессионным loopback Bearer-токеном.
- Отказ 404 при попытке выбрать документ другого Matter; сведения о нём
  не включаются ни в JSON-ответ, ни в Word.
- Проверка целостности обязательна, ошибка 409 блокирует результат.
- Максимум 12 источников, 250 чанков / 800 000 символов / 100 явно
  размеченных значений на источник. При превышении лимита API возвращает
  413 без частичного отчёта.
- Справка не сохраняется в Supabase, не отправляется в Telegram/почту/суд
  и не передаётся внешним AI-провайдерам.
- Результат не формируется автоматически, возможен только явный
  экспорт редактируемого DOCX через macOS Save Panel.

## API

POST /v1/matters/{matter_id}/evidence/matrix

POST /v1/matters/{matter_id}/evidence/matrix/docx

Тело:

~~~json
{
  "source_document_ids": ["first-owned-document-id", "second-owned-document-id"],
  "comparison_subject": "Договор, который пользователь решил проверить"
}
~~~

Первый endpoint возвращает структурированные источники, сравнения, значения
без пары, предупреждения и число потенциальных различий. Второй повторно
проверяет документы и формирует DOCX со статусом «внутренняя проверочная
справка». Факты не добавляются за пределами найденных размеченных строк.

## Приёмка

- Python CI, тесты parser/normalization, cross-Matter isolation, Auth,
  integrity failure, size limits, DOCX round-trip, Swift contract.
- Apple iOS Simulator / macOS builds; unsigned macOS Packaging.
- На чистом Mac: загрузка синтетических двух документов, сверка,
  визуальная проверка ссылок, экспорт и открытие Word, смена Matter,
  отказ при недоступном локальном сервисе.

Ограничения: алгоритм не извлекает естественно-языковые обстоятельства,
показания свидетелей, связи между лицами, причинность, процессуальные
нарушения или правовые оценки. Это отдельная будущая задача, требующая
разметки источников, контролируемых гипотез и проверки юристом.
