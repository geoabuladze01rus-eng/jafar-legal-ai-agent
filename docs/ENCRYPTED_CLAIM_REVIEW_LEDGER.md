# JAFAR 2.1 — локальный журнал решений юриста по расхождениям

## Процессуальная цель

После получения гипотезы о расхождении между двумя документами пользователь
сам определяет дальнейшую работу: оставить гипотезу для анализа, отклонить её
или запросить недостающие материалы. Любое решение требует пояснения,
написанного пользователем.

Запись не подтверждает достоверность высказываний, авторство показаний,
смысл события или юридическую квалификацию. Статус «Оставить для работы»
не означает «подтверждено».

## Интерфейс

1. В «Аналитике» выбрать Matter и провести локальную проверку высказываний.
2. Нажать «Зафиксировать решение по этому расхождению» для конкретной пары.
3. Вписать собственное пояснение не короче пяти символов.
4. Выбрать «Оставить для работы», «Отклонить» или «Нужны документы».
5. Запись сохраняется в зашифрованном локальном журнале. Последнее
   решение по паре показывается на карточке; прежние записи сохраняются.
6. Можно вручную сохранить внутренний «Реестр проверок юриста.docx».

При смене Matter прежнее выделение, пояснение и список решений
очищаются из интерфейса.

## Безопасность

Журнал хранится только в Application Support/JAFAR/claim-review-decisions.sqlite3.
Ключ AES-256-GCM получается из существующего Keychain-derived corpus key
отдельным HKDF-контекстом. Шифруются пояснения, цитаты, участники
и сведения по материалам дела. В SQLite остаются лишь технические
идентификаторы дела и записей, а также время.

Перед сохранением сервер повторно проверяет отчёт по зашифрованным
оригиналам: Matter, цитаты, технические источники и происхождение
физических страниц PDF. Пары пересчитываются сервером. Нельзя
сохранить произвольный candidate_id, подменить исходную цитату или
включить документ другого дела.

Записи добавляются, а не перезаписываются. Лимит 300 событий на Matter.
При неверном ключе или повреждении шифротекста чтение блокируется.
Удаление/откат всей базы пользователем с доступом к диску этот
механизм обнаружить не гарантирует. Это не юридически удостоверенный
журнал судебных действий.

Нет автоматической отправки, синхронизации Supabase, облачных AI
или подачи процессуальных документов.

## API

GET /v1/matters/{matter_id}/claims/decisions

POST /v1/matters/{matter_id}/claims/decisions

POST принимает JSON-объект report (полный ClaimReviewReport) и decision
с candidate_id, decision и note. Статусы: keep_for_work, dismissed,
needs_sources. Операция выполняется только после проверки источников.

GET /v1/matters/{matter_id}/claims/decisions/docx

Все маршруты доступны только в desktop режиме за локальным Bearer-токеном.
Чужой Matter — 404. Неверный candidate_id или изменённая цитата — 422.
Нарушение целостности — 409. Превышение лимита — 413.

## Приёмка

Синтетические тесты: запись, перезапуск, шифрование заметок и цитат,
изоляция Matter, неверный ключ, изменение шифротекста, подмена цитаты,
повреждение оригинала, авторизация, отсутствие повторного обращения
к модели при фиксации решения, внутренний DOCX.

Отдельно необходимы CI, iOS/macOS сборки и упаковка macOS.
На чистом Mac проверить повторное открытие, смену Matter,
восстановление локального ключа, политику хранения и резервное копирование.
