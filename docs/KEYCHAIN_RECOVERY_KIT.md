# JAFAR 2.1 — аварийное восстановление ключа macOS Keychain (закрытая бета)

## Что защищает набор восстановления

Зашифрованная копия юридического архива (PR №102) НЕ содержит мастер-ключ
локального JAFAR. Поэтому при полном отказе или утрате Mac архив без ключа
не откроется. Этот блок добавляет **отдельный переносной зашифрованный набор
для восстановления мастер-ключа**.

Мастер-ключ хранится в macOS Keychain как 32 байта. Утилита чтения не создаёт
новый ключ. Экспорт упаковывает существующий ключ в файл с независимым
шифрованием PBKDF2-HMAC-SHA256 (600 000 итераций, случайная соль) и
AES-256-GCM. Содержимое не печатается в терминале, не добавляется
в файлы проекта, почту, Telegram или Supabase.

Выбор места хранения файла и парольной фразы производится пользователем.
Пароль вводится в терминале без отображения и не передаётся как аргумент.

## На действующем Mac: создание recovery-kit

Полностью закройте JAFAR, убедитесь, что локальный backend остановлен.
Используйте установленный Xcode Command Line Tools и исходный репозиторий.

~~~bash
swiftc -o /tmp/jafar-key-recovery scripts/jafar_key_recovery.swift

/tmp/jafar-key-recovery status

/tmp/jafar-key-recovery export \
  --output "/Volumes/SAFE-USB/JAFAR-key-recovery.json"
~~~

Задайте и подтвердите **новую отдельную фразу минимум из 20 символов**,
отличную от пароля резервного архива. Сохраните recovery-kit в защищённом
офлайн-хранилище, желательно отдельно от основной резервной копии.
Нельзя хранить оба файла и пароли вместе на единственном компьютере.

Файл содержит зашифрованный мастер-ключ. Утрата файла или пароля может
сделать аварийное восстановление невозможным. Получивший файл и пароль
сможет расшифровать скопированные клиентские данные.

## На новом Mac: порядок восстановления

Это инструкция для пустого профиля JAFAR. **Не запускайте JAFAR** до
восстановления ключа и данных.

1. Установите CLI из проверенного исходного проекта.
2. Проверьте наличие ключа командой status: ключ должен отсутствовать.
3. Восстановите ключ командой import. Это сохранит ровно тот 32-байтовый
   мастер-ключ в Keychain с атрибутом ThisDeviceOnly:

~~~bash
/tmp/jafar-key-recovery import \
  --input "/Volumes/SAFE-USB/JAFAR-key-recovery.json"
~~~

4. Снова проверьте status.
5. Убедитесь, что каталог
   "$HOME/Library/Application Support/JAFAR" **не существует**.
   При наличии каталога нельзя перезаписывать его. Нужно отдельно
   исследовать его содержимое и исключить потерю работы.
6. Восстановите зашифрованный архив с PR №102 в **новый** каталог:

~~~bash
python -m jafar.desktop_backup restore-new \
  --archive "/Volumes/SAFE-USB/JAFAR-backup.jafarbackup" \
  --target "$HOME/Library/Application Support/JAFAR"
~~~

7. Проверьте доступность юридических материалов на закрытом
   тестовом Mac. Только после полной проверки открывайте JAFAR
   для реальной работы.

Для чтения recovery-kit нужен его отдельный пароль. Для открытия
архива нужен **другой пароль**. Они выполняют разные функции.

Если в Keychain уже существует ключ с тем же именем,
импорт **запрещён**: утилита не удаляет и не заменяет ключ.
Если существующая локальная база есть, а ключа нет,
JAFAR теперь блокирует автоматическую генерацию нового ключа.
Это защищает от незаметного создания новой криптографической личности.

## Реализованные ограничения

- Операции экспорта и импорта только интерактивные: пароль нельзя передать
  через аргумент CLI или выполнить неинтерактивно в CI.
- Обе операции блокируются, если локальный процесс удерживает matters.lock.
- Экспорт создаёт файл с правами 0600 и только при отсутствии целевого пути.
- Импорт возможен лишь после успешной AES-GCM проверки пароля и содержимого.
- Существующий Keychain item никогда не обновляется или удаляется.
- Метод хранения исходного ключа остаётся ThisDeviceOnly;
  recovery-kit — независимая пользовательская копия.
- Self-test выполняется без обращения к настоящему Keychain и использует
  исключительно случайный синтетический ключ.
- Компонент на этапе бета доступен только как отдельная Swift CLI-утилита,
  не как кнопка интерфейса приложения.
- Контроль PIN/Touch ID, физической безопасности USB, escrow, ротация и
  корпоративные правила хранения recovery-kit не реализованы.

## Что должен проверить принимающий специалист

1. Полный Python CI и сборку Apple.
2. Компиляцию Swift CLI непосредственно на macOS.
3. Self-test: правильный пароль, неправильный пароль и подмена шифротекста.
4. На отдельном учебном macOS-пользователе:
   экспорт Keychain → отсутствие ключа → импорт в пустой Keychain →
   восстановление тестового архива → запуск JAFAR.
5. Отказ при работающем backend и при уже существующем ключе.
6. Отказ при существующем каталоге назначения.
7. Читаемость данных после восстановления, точность цитат и Word,
   повторное открытие документов и черновиков.

Ни одна автоматическая CI-проверка не заменяет пользовательскую процедуру
хранения паролей и испытание на отдельном Mac с реальным Keychain.
**До этой приёмки не использовать для клиентских дел.**
